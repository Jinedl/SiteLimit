# SiteLimit

Android-приложение, которое ограничивает время на отдельных сайтах в **Яндекс Браузере** (обычном, Lite, бета) и в приложении **«Яндекс — с Алисой»** — как StayFocusd на компьютере. Готовые блокировщики (AppBlock, StayFree, BlockSite) Яндекс Браузер не поддерживают, поэтому здесь своя служба специальных возможностей.

## Как работает

- Служба специальных возможностей следит только за браузерами Яндекса: `com.yandex.browser` (+ `.lite`, `.beta`, `.alpha`) и «Яндекс — с Алисой» (`com.yandex.searchapp`, `ru.yandex.searchplugin`).
- Раз в секунду читает адресную строку и добавляет секунду к сайту, если для него задан лимит. Поддомены считаются вместе: лимит на `youtube.com` действует и на `m.youtube.com`.
- Если адресная строка спряталась при прокрутке, сайт считается прежним. Другой адрес в строке сбрасывает текущий сайт.
- При выключенном экране и в других приложениях время не идёт.
- Когда дневной лимит исчерпан — через 1,5 секунды (успеть переключить вкладку) переход на главный экран и окно «Лимит исчерпан». Лимит сбрасывается в полночь.
- Список вкладок, главная Яндекса и экран поиска сайтом не считаются.
- Данные хранятся только на телефоне, в интернет приложение не ходит (разрешения на интернет у него нет).

## Установка APK

1. Откройте на телефоне страницу последней версии: **https://github.com/Jinedl/sitelimit/releases/latest**
2. В разделе *Assets* нажмите на `SiteLimit-X.Y.apk` — файл скачается.
3. Откройте скачанный файл. Если телефон спросит, разрешите браузеру «Установку неизвестных приложений» и вернитесь назад.
4. Нажмите «Установить». Play Защита может предупредить о неизвестном разработчике — «Всё равно установить».

Новые версии ставятся так же, поверх старой: лимиты и статистика сохраняются.

## Включение службы

1. Откройте SiteLimit → кнопка **«Открыть Специальные возможности»**.
2. Найдите **«SiteLimit — лимиты сайтов»** (иногда в разделе «Скачанные приложения» / «Установленные службы») и включите.
3. **Если переключатель серый и пишет «Ограниченная настройка»** (Android 13 и новее, для приложений не из магазина):
   1. Нажмите на серый переключатель один раз и закройте сообщение — без этого нужный пункт меню не появится.
   2. Настройки → Приложения → **SiteLimit**.
   3. Меню **⋮** в правом верхнем углу → **«Разрешить ограниченные настройки»** → подтвердите PIN-кодом или отпечатком.
   4. Вернитесь в Специальные возможности и включите службу.
4. В приложении должно появиться «Служба: включена ✅».

Если служба сама выключается — разрешите SiteLimit работать без ограничений в настройках батареи (Настройки → Приложения → SiteLimit → Батарея → «Без ограничений»).

## Пользование

- Введите сайт (`youtube.com`) и минуты в день → «Добавить». Тот же сайт с другим числом меняет лимит.
- В списке видно «сайт — N из M мин». Долгое нажатие — удалить.

## Отладка адресной строки

Если «Сейчас в браузере» показывает не тот сайт или «—»:

1. Включите галочку «Сохранять снимок окна браузера».
2. Откройте сайт в Яндекс Браузере, подождите 3–5 секунд, вернитесь в SiteLimit.
3. «Показать снимок» → «Копировать» и пришлите текст. В снимке есть все элементы окна браузера (кроме содержимого страницы) с их `id` и текстом.
4. Если видно, у какого `id` в тексте адрес сайта, впишите этот `id` в поле «свой id адресной строки» → «Сохранить». Тогда служба будет брать адрес именно из него.

## Типы контента (бета, ветка feature/content-types)

Лимиты не на приложение целиком, а на тип экрана: переписка без лимита, а каналы, ленты и ролики — по минутам и открытиям.

- **Выключатель** «Типы контента (бета)» на главном экране. Выключен — приложение работает как 0.9 (только сайты), служба получает события только от браузеров.
- **Сервисы**: Telegram, Max, VK, YouTube (приложения). Сайты — как раньше, лимит на домен целиком (путь вроде `/shorts` в адресной строке не виден).
- **Типы**: переписка; каналы и паблики; лента и рекомендации; короткие ролики; длинное видео; поиск и служебное; «неизвестно» — не ограничивается никогда.
- **Распознавание** — по файлу правил `app/src/main/assets/content_rules.json` (id, класс, текст, описание элементов окна). Правила можно заменить без новой версии: Отладка → «Свои правила».
- **Счётчики**: минуты и открытия в день по сервису и типу, сброс в полночь, хранение 60 дней. Открытие — вход в тип из другого типа того же сервиса (всегда) или из другого приложения, с выключенного экрана, через неизвестный экран — если тип не был на экране больше 5 с. Вход в закрытый тип открытием не считается. Неизвестный экран в том же приложении открытие не прерывает.
- **Лимиты** у каждого режима свои: по сервису и типу (минуты, открытия; пусто — без лимита, 0 — закрыто) и общие на несколько типов во всех сервисах вместе.
- **Исключения** по названию канала или чата (или по сайту): «всегда можно», «всегда нельзя», «считать каналом» (большой чат по лимиту каналов).
- **Режимы**: «Обычный», «Только общение», «Учёба/Работа», «Отдых»; по расписанию (дни, время) и вручную на срок. Пресеты применяются к режиму и дальше редактируются. **Упрямый режим**: пока идёт, правила можно только ужесточать; режим, расписание и выключатель беты не поменять. Защиты от отключения службы или смены времени на телефоне нет.
- **Блокировка**: 1,5 с на переход, затем «Назад»; если через 0,7 с экран всё ещё под запретом — «Домой». Затем окно «Лимит исчерпан» с сервисом, типом и причиной.
- **Нагрузка**: события только от нужных пакетов и только двух видов (окно сменилось, содержимое изменилось), не чаще раза в секунду. Разбор окна идёт запросами в главный поток самого приложения, поэтому: при прокрутке — не чаще раза в 1 с, при смене экрана и во время 1,5 с на переход — раз в 0,3 с, без событий — раз в 4 с; у прокручиваемых списков читаются только первые 4 видимых элемента; всего до 300 элементов; содержимое WebView пропускается.

### Снимки для настройки правил

1. Долгое нажатие на строку версии → Отладка → галочка «Сохранять снимки окна».
2. Откройте нужный экран в сервисе, подождите 3–5 с, переключитесь в SiteLimit через «Недавние».
3. «Снимки сервисов» → нужный снимок → «Копировать». Хранятся 6 последних разных экранов; прокрутка того же экрана обновляет его снимок, а не добавляет новый.
4. По умолчанию буквы скрыты (•), цифры — 0, кроме слов из правил; тексты обрезаны; название канала в строке «Сейчас» тоже скрыто. У списков в снимке только первые 4 элемента. Перед отправкой всё равно проверьте, что нет личного. После снимков выключите галочку.

### Файл правил

```json
{"services": [{"id": "telegram", "title": "Telegram",
  "packages": [{"name": "org.telegram.messenger", "status": "guess"}],
  "screens": [
    {"id": "tg_channel", "type": "channel", "status": "src",
     "any": [{"textRe": "^\\d[\\d\\s.,]*\\s*подписчик", "yMax": 0.12}],
     "title": {"from": {"textHas": "подписчик"}, "pick": "above", "field": "text"}}
  ]}]}
```

- Правила сервиса проверяются сверху вниз, срабатывает первое; не сработало ни одно — «неизвестно».
- `all` — для каждого условия нашёлся элемент; `any` — хотя бы для одного; `none` — ни для одного; `packages` — только для этих пакетов.
- Условие на один элемент: `id`, `idHas`, `cls`, `clsHas`, `text`, `textHas`, `textRe`, `desc`, `descHas`, `descRe`, `anyHas`, `anyRe` (текст, описание или подсказка), `hintHas`, `selected`, `checked`, `editable`, `clickable`, `yMin` / `yMax` (доля высоты экрана для верха элемента), `min` (сколько элементов). Без учёта регистра.
- `title` — откуда взять название (для исключений): элемент `from`, `pick` self / above / below, `field` text / desc / any, `re` с группой 1.
- `status`: snap — по снимку с телефона, src — по исходному коду, guess — догадка. Поля, начинающиеся с `_`, игнорируются (комментарии).
- В снимках буквы скрыты, поэтому «34.5K подписчиков» выглядит как «00.0• подписчиков»: в шаблонах чисел допускается и «•».

### Что распознаётся (0.10-beta2)

✅ — снимок с телефона в тестах или проверка владельца; 🔶к — по исходному коду; 🔶 — догадка; «—» — правила нет или такого экрана в сервисе нет (будет «неизвестно», не блокируется); ✗ — нельзя.

| | Переписка | Каналы | Лента | Короткие | Видео | Поиск |
|---|---|---|---|---|---|---|
| Telegram | ✅ | ✅ | — | — | — | ✅ |
| Max | 🔶 | 🔶 | — | — | — | 🔶 |
| VK | ✅ | 🔶 | 🔶 | 🔶 | ✅ | ✅ |
| YouTube | — | ✅ | ✅ | 🔶к | 🔶 | ✅ |
| Сайты | ✗ | ✗ | ✗ | ✗ | ✗ | ✗ |

Подробности: Telegram — список чатов, канал, поиск по снимкам; личный чат, группа, комментарии — проверка владельца. VK — Мессенджер, раздел «Видео», поиск, «Сервисы» по снимкам; Главная — запасное правило без снимка; клипы закрываются (проверка владельца), но каким правилом — неизвестно. YouTube — поиск, «Подписки», страница канала по снимкам; «Главная» — то же правило, что «Подписки»; плеер видео и Shorts — без снимков. У сайтов — лимит на домен целиком, как в 0.9.

## Сборка и подпись

Сборка идёт только в GitHub Actions (`.github/workflows/build.yml`) при каждом пуше в `main` и в ветки `feature/**`; перед сборкой запускаются JVM-тесты (`app/src/test`). В `main`: если версия (`versionName` в `app/build.gradle.kts`) новая, подписанный APK публикуется в GitHub Release `vX.Y`. В ветке: публикуется только версия с суффиксом (`0.10-beta1`) — как prerelease, ссылка `releases/latest` на неё не ведёт.

APK подписывается **постоянным** ключом — иначе новые версии не установятся поверх старых. Ключ создаётся один раз workflow `keygen.yml`, шифруется (AES-256, PBKDF2) паролем из секрета `SIGNING_PASSWORD` и хранится в репозитории как `signing/release.p12.enc`. Без пароля файл бесполезен, поэтому пароль должен быть длинным и случайным.

Один раз нужно:

1. Придумать пароль не короче 16 символов (лучше сгенерировать в менеджере паролей) и **сохранить его** — посмотреть секрет потом нельзя.
2. Repository → Settings → Secrets and variables → Actions → New repository secret: имя `SIGNING_PASSWORD`, значение — пароль.
3. Actions → «Создать ключ подписи (один раз)» → Run workflow. Он создаст ключ и сам запустит сборку.

Не удаляйте `signing/release.p12.enc` и не меняйте секрет: с новым ключом обновить установленное приложение не получится, придётся удалять его вместе с данными.
